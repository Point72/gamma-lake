# Benchmarking

GammaLake includes portable [ASV](https://asv.readthedocs.io/) benchmarks for
`GammaFeatureLake.add_features()` and `GammaFeatureLake.read()`.

Install development dependencies and initialize ASV's machine metadata once:

```bash
make develop
make benchmark-init
```

Run the full suite or a single-pass smoke run:

```bash
make benchmark-check
make benchmark
make benchmark-quick
```

CI can use `make benchmark-ci`, which runs the full suite while treating ASV's
timeout status as non-fatal and still failing on other errors.

Results and reports are generated under `.asv/`. Use `make benchmark-publish`
to build the HTML report, `make benchmark-view` to preview it, and
`make benchmark-clean` to remove generated benchmark data and reports.

## Storage

Benchmarks use unique paths under `.asv/benchmark-data` by default and remove
only paths generated by the harness. Override the local root if needed:

```bash
GAMMALAKE_BENCH_LOCAL_ROOT=/path/with/free-space make benchmark
```

S3 is optional. Set a bucket and non-empty prefix to enable it:

```bash
GAMMALAKE_BENCH_S3_PREFIX=s3://my-bucket/my-prefix make benchmark
```

GammaLake and boto3 use the standard AWS credential chain, including
environment variables, shared AWS configuration, and instance or workload
roles. The benchmark harness does not fetch or configure credentials.

## Suite parameters

- `GammaLakeWriteSuite`: six sequential merge writes covering existing and new
  symbols, future dates, and new feature groups.
- `GammaLakeOverlapWriteSuite`: eight sequential writes covering full and
  partial temporal overlaps, new feature columns, and full re-merges.
- `GammaLakeReadSuite`: 1, 7, and 30 day windows across 1 or 3 feature groups.

The sequential write scenarios use 3 features, 5 to 20 symbols, and 10-day
windows. The overlap and read suites use 200 symbols, 50 features per group,
and 30-day base windows.
